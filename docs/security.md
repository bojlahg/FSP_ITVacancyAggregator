# Безопасность и 152-ФЗ

## 1. Персональные данные и согласия

| Требование | Реализация |
|---|---|
| Согласие на обработку ПДн | обязательная отметка при регистрации; запись в `consents` с версией текста политики и датой; отозвать можно только удалением аккаунта (иначе 409 `consent_required`) |
| Согласие на публикацию профиля | отдельная отметка; без неё кандидат не виден в поиске; отзыв в настройках сразу убирает профиль из выдачи |
| Согласие на импорт ФСП | при привязке ФСП ID; отзыв удаляет импортированные данные ФСП |
| Минимизация | в БД попадают только данные, подтверждённые пользователем: разбор резюме возвращается как черновик формы, профиль меняется только после подтверждения |
| Право на удаление | `DELETE /candidates/me`: ФИО и контакты стираются, опыт, резюме (вместе с файлом) и данные ФСП удаляются, профиль убирается из выдачи, активные приглашения истекают, сессии и согласия отзываются, email заменяется на `deleted-<id>@deleted.invalid` |
| Локализация | данные хранятся на сервере в РФ (VDSina); LLM — Yandex AI Studio, данные не уходят за рубеж. LLM выключается одной настройкой (`LLM_PROVIDER=none`), продукт полностью работает без него |
| Аудит | журнал `audit_log`: раскрытие контактов, изменение согласий, привязка ФСП |

## 2. Видимость данных

- **Контакты кандидата** не отдаются работодателю ни одним эндпоинтом, включая PDF-профиль, пока нет записи в `contact_unlocks`: она появляется только при принятии приглашения или отклике кандидата. Обезличенная карточка показывает имя и первую букву фамилии, без контактов и названий компаний; из свободного текста («О себе», описания опыта, ответ на открытый вопрос теста) вычищаются email, телефоны, Telegram и ссылки — и в API, и в PDF (тест `test_free_text_hides_contacts_until_unlock`).
- **Слепой первый просмотр:** без фото, возраста и пола.
- **Приватность кандидата:** показывать ли фамилию, достижения ФСП и зарплатные ожидания; список компаний, от которых профиль скрыт полностью (например, текущий работодатель).
- **Разграничение по объектам:** кандидат видит только свои приглашения, отклики и задания; работодатель — только свои потребности, приглашения и задания. На каждое правило есть тест «чужое → 403/404» (`backend/tests/test_invitations.py`, `test_applications.py`, `test_privacy.py`, `test_tasks.py`).
- **Ключи ответов** на тест и задания никогда не уходят на фронт, даже работодателю в предпросмотре теста под вакансию; e2e-тест проверяет отсутствие ключей в ответах API.

## 3. Аутентификация и сессии

| Механизм | Реализация |
|---|---|
| Пароли | argon2id (`argon2-cffi`) |
| Access-токен | JWT HS256, живёт 15 минут, передаётся в заголовке `Authorization` |
| Refresh-токен | случайный токен в httpOnly cookie на путь `/api/v1/auth` (флаг Secure — настройка `COOKIE_SECURE` для HTTPS), в БД — только sha256-хэш; ротация при каждом обновлении; повторное использование отозванного токена отзывает все сессии пользователя |
| Подтверждение почты | одноразовый токен на 24 часа, в БД — хэш |
| Защита от подбора | ограничение частоты `/auth/*`: 20 запросов в минуту на IP и путь, сверх — 429 |
| Роли | `candidate`, `employer`, `admin` проверяются dependency-функциями FastAPI |
| Секрет JWT | в проде обязателен свой `JWT_SECRET` от 32 символов — иначе приложение не стартует |
| ФСП ID | OIDC authorization code + PKCE S256, проверка `id_token` по JWKS (только асимметричные алгоритмы), `state` и `nonce` в подписанной httpOnly cookie |

**Реальный IP для лимита.** Backend доступен только из сети compose через Caddy; Caddy без настроенных `trusted_proxies` не доверяет входящему `X-Forwarded-For` и выставляет его сам, а uvicorn (`--proxy-headers`) берёт из него адрес клиента. Поэтому лимит считается по реальному IP посетителя, подменить его заголовком нельзя.

## 4. Тестирование

- Ответ принимается только на текущее задание попытки; время показа и ответа фиксирует сервер, ответ после лимита времени (с запасом 5 секунд на сеть) не засчитывается.
- В интерфейсе теста отключены копирование и контекстное меню, уходы со вкладки фиксируются флагом попытки.

## 5. Инфраструктура и секреты

- HTTPS с сертификатом Let's Encrypt (Caddy), запросы к домену по HTTP редиректятся на HTTPS.
- Наружу открыт только Caddy (порты 80/443). Backend, Postgres, мок реестра и Keycloak доступны лишь внутри сети compose; у Keycloak наружу открыт только realm `fsp`, админка и realm `master` закрыты.
- CORS — только собственный домен.
- Секреты — только в `.env` на сервере (права 600) и в GitHub Secrets (ключ деплоя); в репозитории — `.env.example` без значений. Мок реестра ФСП принимает запросы только с API-ключом.
- Почта: собственный Postfix только на отправку, письма подписаны DKIM.
