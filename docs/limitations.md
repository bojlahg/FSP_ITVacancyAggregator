# Ограничения MVP и планы

Честный список того, что в прототипе упрощено или не сделано, и что делаем дальше.

## Тестирование

| Ограничение | Почему так | Что дальше |
|---|---|---|
| Параметры шаблонов (a, b) — экспертные оценки, не калибровка на людях | живых ответов нет; симуляция показывает, что ошибка b с σ = 0,25 почти не влияет на точность категории | пилотные слоты в каждой попытке уже собирают ответы; перекалибровка методом fixed-parameter MML (проверен в валидации), шаблон становится `active` после ~400 ответов |
| Пороги грейдов стартовые | для modified Angoff нужны эксперты | панель из 3–5 ИТ-специалистов на каждую специализацию |
| Банк: 47–106 шаблонов на специализацию; мало лёгких (b < −1) и трудных (b > 1,4) | время хакатона | ≥ 79 шаблонов на специализацию для порога экспозиции 25%, 8–10 лёгких и 4–6 трудных шаблонов в каждую |
| Person-fit, флаг «подозрительно быстрые верные ответы», мониторинг дрейфа шаблонов | нужны накопленные данные | статистика показов и верных ответов по шаблону уже копится в `template_stats` |
| Нет живого coding-задания с песочницей | безопасный запуск кода — отдельная инфраструктура | интеграция с тестирующей системой ФСП |
| Тесты есть для 5 специализаций из 9 | fullstack, mobile, analyst, gamedev — в справочнике со статусом «скоро» | банки для них, fullstack — из шаблонов backend и frontend |
| Грейд Lead не поддерживается | нужна оценка управленческих навыков | — |

## Подбор и данные

| Ограничение | Что дальше |
|---|---|
| Порядок внутри категории проверен только симуляцией | экспертная разметка 100 пар «потребность — кандидат» (функции метрик готовы) |
| «Общий топ» уступает группировке по категориям | группировка — режим по умолчанию; усилить штраф соседнего грейда в `content/matching.yaml` |
| Разбор резюме не измерен по precision и recall | разметка 30 синтетических и 5–10 реальных резюме |
| Сканы PDF без текстового слоя не распознаются | OCR |
| Данные ФСП — мок; список дисциплин и ролей — наше предложение | сверка с экспертами ФСП, подключение реального API реестра и ФСП ID без правок кода |
| Импорт ФСП — только при привязке | webhook реестра о новых результатах или ежедневный повторный импорт |

## Платформа

| Ограничение | Что дальше |
|---|---|
| Подтверждение почты не обязательно (`EMAIL_VERIFICATION_REQUIRED=false`) до проверки доставляемости писем | включить после настройки SPF, DKIM, DMARC и PTR |
| Верификация работодателей, модерация и готовые коннекторы к ATS — концепция (API-ключи, webhook'и и экспорт в JSON Resume работают) | см. [anti-fraud-ats.md](anti-fraud-ats.md) |
