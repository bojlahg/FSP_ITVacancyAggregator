# ITScout

**ITScout** — платформа ИТ-подбора с обратной механикой для спецтрека ФСП хакатона «Лидеры цифровой трансформации 2026». Кандидат проходит опрос и адаптивный тест и получает категорию «специализация × грейд». Работодатель описывает потребность, получает подборку кандидатов с объяснением и сам отправляет приглашение с обязательной вилкой зарплаты. Контакты кандидата открываются только после того, как он принял приглашение или откликнулся сам.

- Прототип: **https://itscout.ru** (вход в кабинеты — кнопками демо-входа на странице входа)
- Swagger UI: https://itscout.ru/api/docs, контракт — [`backend/openapi.json`](backend/openapi.json)
- Документация одним файлом: [`docs/ITScout-docs.pdf`](docs/ITScout-docs.pdf)
- Лицензия: [MIT](LICENSE)

## Как это работает

```mermaid
flowchart LR
  subgraph Кандидат
    R[Регистрация<br/>и согласия] --> S[Опрос →<br/>специализация] --> G[Выбор грейда] --> T[Адаптивный тест] --> C[Категория<br/>Backend · Middle]
  end
  subgraph Работодатель
    N[Потребность<br/>текстом, с вилкой] --> P[Подборка:<br/>категории + кандидаты<br/>с объяснением] --> I[Приглашение<br/>с вилкой]
  end
  C --> P
  I --> A{Кандидат<br/>принял?}
  A -- да --> K[Контакты открыты<br/>обеим сторонам]
  A -- нет --> D[Причина отказа →<br/>статистика работодателю]
```

1. **Категорию определяет тест, а не резюме.** Банк из 595 параметризованных шаблонов (574 активных: 565 заданий с автопроверкой и 9 открытых вопросов) на общей IRT-шкале, двухэтапный адаптивный тест, оценка способности EAP и решение о грейде по порогам.
2. **Подборка объяснима.** Score и объяснение считаются одним кодом из одних и тех же компонентов: категория, проверенные навыки, сила результата теста, ФСП, свежесть, условия.
3. **ФСП — бонус, а не штраф.** Достижения из реестра ФСП (мок) поднимают кандидата в выдаче и подтверждают компетенции. Профиль без ФСП полностью работоспособен.
4. **Собственная валидация — на симуляции.** Живых ответов до запуска нет, поэтому механику проверили на 2 000 синтетических кандидатах тем же движком: категория совпала с истинным грейдом у 81,5%, ошибок больше чем на один грейд в прогоне не было. При утечке 30% ключей доля ложно прошедших у ITScout выросла на 1 п.п., у фиксированного теста — на 48 п.п. Выдача ITScout на синтетической релевантности даёт P@5 0,69 (±0,06) против 0,28 у поиска по ключевым словам резюме. Простой фильтр «категория по тесту + ключевые слова» набирает 0,76: синтетическая истина знает только специализацию, грейд и стек, а выдача внутри категории дополнительно упорядочивает по силе подтверждённого профиля, проверенным навыкам и условиям — этого метрика не видит; порядок внутри категории проверяет экспертная разметка ([отчёт, §10](docs/validation/report.md#10-подбор)). Параметры IRT заданы экспертно и проверены на симуляции; калибровка на живых ответах — первый шаг после запуска ([отчёт](docs/validation/report.md), [ограничения](docs/limitations.md)).
5. **Второй путь к кандидату — через решение.** Работодатель даёт кандидатам категории короткое задание из банка или публикует челлендж со своими вопросами. Решения он видит с результатом и обезличенной карточкой (имя и первая буква фамилии, без контактов) и приглашает автора с вилкой прямо из списка решений. Верное решение задания подтверждает навык в профиле кандидата; челлендж на грейд и навыки не влияет.

## Посмотреть за 5 минут

1. **Видео** сквозного сценария, 3,5 минуты: [docs/ITScout-demo.mp4](docs/ITScout-demo.mp4).
2. На [itscout.ru](https://itscout.ru) — «Посмотреть как работодатель» → «Потребности» → «Backend-разработчик в платёжную команду» → «Открыть подборку». У кандидатов — score и строки «почему»: что проверено тестом, что только заявлено. Закрепите двоих в шорт-листе, откройте карточку Анны К. и нажмите «Пригласить»: вилка подставится из потребности — отправьте приглашение.
3. Во втором окне (инкогнито) — «Посмотреть как кандидат»: «Приглашения» → «Подробнее» → «Почему вам» → «Принять». В первом окне в «Приглашениях» у Анны появятся контакты.
4. [«Как работает тест»](https://itscout.ru/how-it-works) — механика теста вживую: шаблоны, экземпляры, устойчивость к утечке.

Демо-аккаунты общие для всех посетителей. Для своего сценария зарегистрируйтесь: это минута, ссылка подтверждения придёт на почту (проверьте «Спам»).

## Демо-доступы

| Роль | Как войти | Что посмотреть |
|---|---|---|
| Кандидат Анна Ковалёва (Backend · Middle, есть ФСП) | «Вход» → блок «Демо-вход» → «Кандидат» | категория и разбор по темам, приглашения с «почему вам», вакансии, задания, привязка ФСП ID |
| Работодатель «Демо Банк» | «Вход» → «Демо-вход» → «Работодатель» | потребности, подборка с объяснением, шорт-лист, приглашения, «Проверка под вакансию» |
| Новый пользователь | «Регистрация» | весь путь кандидата с нуля: опрос → тест → категория |
| Участник ФСП в мок-IdP | кнопка «Войти через ФСП ID» в настройках кандидата | логины — в `infra/keycloak/fsp-realm.json` и [docs/fsp-integration.md](docs/fsp-integration.md) |

## Быстрый старт

```bash
git clone https://github.com/bojlahg/FSP_ITVacancyAggregator.git itscout && cd itscout
cp .env.example .env            # задать POSTGRES_PASSWORD и KEYCLOAK_ADMIN_PASSWORD, см. docs/deploy.md
docker compose --env-file .env -f infra/docker-compose.yml up -d --build
docker compose --env-file .env -f infra/docker-compose.yml exec backend python -m seed.generate
# → http://localhost
```

Подробно, в том числе режим разработки и запуск без Docker, — в [docs/deploy.md](docs/deploy.md).

## Стек

Python 3.12, FastAPI, SQLAlchemy 2 (async), Alembic, numpy/scipy · PostgreSQL 16 · React 19, Vite, TypeScript, TanStack Query, Tailwind · Caddy, Docker Compose, GitHub Actions · Keycloak 26 (мок ФСП ID) · Yandex AI Studio (опционально) · pytest, Playwright.

