# Банк шаблонов заданий

Механика описана в `docs/implementation.md` §10. Шаблон — это семейство изоморфных заданий: одна проверяемая идея и одна сложность. Числа, имена, код, данные, порядок и дистракторы генерируются заново на каждую попытку из seed. Поэтому ключ ответов из чужой попытки не подходит, а выучить шаблон — значит выучить концепцию.

Файлы: `content/templates/<специализация>/<тема>.yaml`, в каждом — список шаблонов. Python-генераторы лежат в `app/modules/testing/engine/generators/<специализация>.py`.

Проверка: `python -m uv run pytest tests/test_bank.py` (в CI обязательна). Валидатор рендерит каждый шаблон на 25 seed и проверяет:
- поля и ссылки на навыки и темы;
- детерминированность рендера;
- нужное число вариантов ответа;
- что экземпляры действительно различаются.

## Поля

| Поле | Обязательно | Описание |
|---|---|---|
| `id` | да | Уникальный: `<префикс специализации>.<тема>.<суть>`, например `be.db.composite_index`. Префиксы: `be`, `fe`, `qa`, `ops`, `ds`, `cmn` |
| `version` | нет | Увеличивать при изменении смысла задания (по умолчанию 1) |
| `specializations` | да | Для каких специализаций: `[backend]`, `[backend, data]` |
| `topic` | да | Тема из `content/blueprints.yaml` → `specializations.<spec>.topics` |
| `stack_module` | для `topic: stack` | `python`, `java`, `go`, `csharp`, `nodejs`, `react`, `vue`, `angular`, `python_ml`, `qa_automation_python`, `qa_automation_java` |
| `skills` | да | id навыков из `content/skills.yaml`: что проверяет задание |
| `kind` | да | `single_choice`, `multi_choice`, `numeric`, `ordering`, `code_output`, `open_approach` |
| `irt` | да | `{a, b}`: a — дискриминация 0.3–3 (обычно 0.8–1.6), b — сложность в логитах |
| `status` | нет | `active` (по умолчанию), `pilot` — не влияет на оценку, `retired` |
| `time_limit_sec` | нет | 90 по умолчанию; код и расчёты — 120–180; `open_approach` — 600 |
| `params` | нет | `имя: {choice: [...]}` или `имя: {int: [от, до], step: N}` |
| `stem` / `stem_variants` | да (без генератора) | Текст с подстановками `{{имя}}`. Несколько формулировок — `stem_variants` |
| `code`, `code_language` | нет | Фрагмент кода с подстановками `{{имя}}`. Одинарные `{}` не трогаются |
| `options.correct` / `options.wrong` | для выбора | Пулы верных и неверных вариантов; движок берёт 1 верный (для `multi_choice` — 2 и больше) и добирает неверные до `n_options` |
| `n_options` | нет | 4 по умолчанию |
| `order_items` | для `ordering` | Элементы в верном порядке, от 3 штук; показываются перемешанными |
| `answer` | для `numeric` | `{expr: "арифметика над {{параметрами}}", tolerance: 0}`; разрешены `+ - * / // % ** min max round abs` |
| `rubric` | для `open_approach` | 3–6 бинарных критериев хорошего ответа |
| `generator` | нет | Имя Python-генератора вместо декларативного описания |

## Шкала сложности b

b задаётся на шкале специализации. Пороги грейдов (`blueprints.yaml` → `scale.cuts`): intern −1.8, junior −0.8, middle 0.2, senior 1.2.

Ориентир: b ≈ порог грейда, на котором «минимально компетентный» специалист решает задание примерно в половине случаев.
- Базовые знания junior — b от −1.8 до −0.6.
- Типовой middle — от −0.2 до 0.8.
- Senior-уровень (тонкости, производительность, архитектурные компромиссы) — от 0.9 до 2.0.

На каждую тему нужен разброс сложности: движок выбирает задания возле порога заявленного грейда.

## Правила хорошего шаблона

- **Параметризация.** Каждый экземпляр должен отличаться: числа, имена, данные, формулировка, набор дистракторов. Шаблон без вариативности валидатор отклонит.
- **Правдоподобные дистракторы.** Это типичные ошибки, а не очевидная чушь. Неверных вариантов в пуле — минимум `n_options − 1`, лучше больше.
- **Сложность не зависит от параметров.** Не делайте так, чтобы при одних значениях задача была тривиальной, а при других — трудной.
- **Только проверенные факты.** Без спорных «лучших практик» и версионно-зависимых мелочей.
- **Числовой ответ считается из параметров** через `answer.expr` или генератор, а не задаётся руками.
- **Генераторы детерминированы.** Только `rng: random.Random` из аргумента — никакого `random.random()`, времени и сети. Код кандидата не исполняется: вывод вычисляется в Python заранее.
- **Тексты на русском.** Названия технологий и код — как есть.
